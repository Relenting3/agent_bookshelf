I split the work by how expensive a mistake is at each step. Opus runs only the planner, where an error multiplies downstream, and the reviewer, which is the quality gate. Sonnet builds and coordinates. Haiku does the mechanical steps (scout, test-runner, pr-writer), which together cost $0.015 per run. Only the orchestrator can start agents, from a fixed allowlist with capped fix rounds, and it stops twice for me: plan approval and before commit. The test-writer works from the plan without seeing the code, in parallel with the implementer, so the tests check the spec rather than the implementation. Run 1 showed the planner at about half of the $1.60 cost, so for Run 2 I lowered its effort from high to medium: the run cost $1.09 with the same fix rounds and verdict. Only about $0.23 of that saving is the lever (the planner's first pass cost 43% less and read nothing outside the scout's map). Another $0.22 came from a plan revision that Run 2 didn't need, which was luck. Next time I'd start with the orchestrator, the second-biggest cost at $0.24–0.32 per run. Every worker runs in the background, so each one that finishes wakes the orchestrator up again, and each wake-up re-reads the whole conversation (22–29 times per run). I'd try having it wait for workers in the foreground instead, so their replies come back without extra wake-ups. Then I'd try the reviewer on Sonnet, since the diff is small. I'd also add hooks to enforce the rules about which files each agent may write, which today are only instructions.
